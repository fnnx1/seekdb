# File-backed exact scan buffering, 2026-11-16

Update, 2026-11-17: the complete official specification has since been located.
Its default workload is 10k rows, so the large-table speedups below do not
explain the default performance score. The formula and cgroup definitions
supersede the missing-specification caveat below; see
[the new report](2026-11-17-score-and-candidates.md).

This change addresses a large-table path absent from the previous 10k-row
benchmark. Relative to the already optimized process-crash default at
`184e413`, 300k-row mixed exact queries improve **3.01x**, and writes plus
queries improve **2.02x**. At 1M rows the corresponding ratios are **2.73x**
and **1.48x**. The 10k-row in-memory workload is essentially unchanged.
These are local measurements, not predictions of formal E or ranking.

## Bottleneck and implementation

The vector store keeps 128 MiB in memory. For pure 128D inserts this is
262,144 vectors; the next stored vector spills the entire prefix to a derived
file. The existing mmap limit is 64 MiB, below the spill threshold, so the
spilled store has no mapped chunks. Previously every file-backed candidate
used a separate 512-byte `pread`. The 32 MiB quantized-cache budget is exceeded
at about 195k rows, so conservative quantized pruning is also absent here.

Each full-scan thread now owns a `VectorStore::ReadBuffer`. A miss reads up
to 64 KiB starting at the requested vector; adjacent candidates reuse these
bytes. Starting at the vector avoids re-reading an aligned window for odd
dimensions. The window can hold a larger individual vector, and its valid
length is limited to the current file end. Sparse filtered scans keep the
existing single-vector read path.

Cached bytes retain the original float32 representation. The distance kernel,
TopK selection, tie ordering, filters, SQL/protocol, WAL format, commit policy,
snapshot ordering, storage thresholds and quantized-cache budget are unchanged.
Every scan has its own buffer; file-backed pointers are evaluated immediately
and never enter the deferred mapped-pointer queue. Store identity and epoch
checks invalidate buffers across release, initialization and moves. Refills
retry EINTR and short reads, and invalidate incomplete windows before errors.

Buffer storage is bounded per scan thread rather than per row. Its logical
size is at most `max(64KiB, vector bytes)`; C++ vector allocation capacity can
exceed its logical size. Queries release the buffers when the scan ends.

## Measurement

Both binaries use the same process-crash commit policy and `g++ -O2`, C++17,
OpenMP. Measurements use Core Ultra 7 265K, btrfs/NVMe data directories,
engine CPUs 0/1 and driver CPU 2. There were no concurrent benchmarks or
correctness suites. Requests and the independent exhaustive integer oracle
are prepared outside measured phases. Inputs are random dyadic float32 with
duplicate random vectors for ties. Each request waits for its response.

All searches are exact Top10: half use a 10%-selective equality filter and
half scan the full table. Every run includes first-query cache construction,
SIGKILL recovery, and oracle validation both before and after restart.
Results are medians over alternating runs; combined phases are summed per
run before taking medians.

| Rows / queries / commits / rounds | Metric | `184e413` | New scan buffer | Ratio |
| --- | --- | ---: | ---: | ---: |
| 10k / 1000 / 100 / 7 | Mixed queries | 26.636 ms | 26.798 ms | 0.99x |
| Same | Writes + queries | 57.256 ms | 57.148 ms | 1.00x |
| 300k / 100 / 300 / 5 | Writes | 0.9613 s | 0.9596 s | 1.00x |
| Same | 50 filtered queries | 0.5852 s | 0.5692 s | 1.03x |
| Same | 50 full-table queries | 2.3796 s | 0.4147 s | 5.74x |
| Same | Mixed queries | 2.9648 s | 0.9839 s | **3.01x** |
| Same | Writes + queries | 3.9238 s | 1.9434 s | **2.02x** |
| Same | Phase sum including recovery | 4.5164 s | 2.5516 s | 1.77x |
| 1M / 40 / 1000 / 3 | Writes | 4.3887 s | 4.2674 s | 1.03x |

| Same | Phase sum including recovery | 11.4082 s | 8.5706 s | 1.33x |

No write, filtered-query or recovery improvement is claimed. The lowest paired
write+query ratio is 1.91x at 300k rows and 1.42x at 1M rows. Thus the change
does not guarantee a universal 1.5x result across workload mixtures.
The phase sum includes startup, schema, writes, initial queries, recovery to
ready and shutdown. It excludes preparation, verification and post-recovery
verification queries, and is not complete process wall-clock time or a device
writeback measurement.

At 300k rows, query-phase Linux read-call accounting decreases from 16,500,100
to 1,617,300; at 1M rows it decreases from 22,000,040 to 2,156,320. These counts
include protocol reads and the unchanged filtered path. Logical read bytes
remain within 0.01%. File-backed vectors are in the kernel cache after loading;
`read_bytes` is zero in these query phases, so cold-storage gains are untested.

Engine peak-RSS medians stay near 172.7-172.9 MiB for the 300k workload and
172.3 MiB for 1M. RSS excludes the kernel page cache and does not establish an
unchanged cgroup M score. No B/M-score improvement is inferred.

## Correctness

`MVDB_SYNC_COMMIT=0 taskset -c 18,19 ./scripts/check.sh` passed completely,
including all existing dynamic, exact-pruning, SELECT-template, WAL, immediate
commit-crash, synchronization-policy, fuzz, large-data, sanitizer and official
host protocol checks (20 public cases). The new tests are included in that
script:

* `tests/vector_store_read_test.cpp`: real 128 MiB spills at 128D and 129D,
  per-coordinate bitwise comparison with a generator and direct reads,
  window boundaries, EOF append, mode switching, move/reinitialization,
  four independent threads, injected EINTR, 137-byte short reads, EIO and EOF.
  ASan/UBSan passes, including a separate OpenMP-enabled build.
* `tests/spill_scan_test.py`: 8193 x 4096D, independently calculated exact
  distances, reverse PK/ties, filters, ascending/descending/offset queries,
  projection, scattered updates/deletes, rollback and failed-statement
  atomicity. It kills immediately after complete COMMIT ACK before JSON
  decoding, kills again at recovery ready, and checks repeated recovery and
  discarded uncommitted changes. Both default and `MVDB_SYNC_COMMIT=1` pass.
* Across the final performance runs, **30,480** initial/recovered query
  responses match the independent exhaustive integer oracle.

No new Docker or formal platform evaluation was run. The platform's latest
provided E remains 3323.891232 for `184e413`.

## Remaining limits

The change targets file-backed full scans. Small in-memory queries, sparse
filters, per-vector writes, WAL encoding and snapshot materialization retain
their existing paths. Extensive updates can scatter vector offsets, reducing
read-ahead benefits and increasing unused bytes. Approximate indexing remains
unimplemented: `search_mode=ann` still receives exact results. ANN performance
is a separate opportunity requiring the complete recall contract.
